# VOLT commerce

A JavaScript Next.js App Router electronics store for Vercel, MongoDB Atlas, Auth.js, Cloudinary and Stripe. See ARCHITECTURE.md for transaction and inventory rules.

## Run

Node.js 24 LTS. `npm ci`, copy `.env.example` to `.env.local`, set `MONGODB_URI`, `AUTH_SECRET` (32+ random bytes), `AUTH_URL` and `NEXT_PUBLIC_SITE_URL`. Use the same canonical origin for the latter two. Set seed administrator email/password (16+ characters), then `npm run seed` and `npm run dev`. Seeding is additive; it never resets inventory or overwrites accounts. Remove seed credentials after use. Admin sign-in: `/admin/login` (no public admin registration); dashboard: `/admin`; customer: `/account`.

MongoDB must support replica-set transactions (Atlas does). All application collections use a volt_ prefix so existing collections in the same database remain separate. Seed initializes indexes before traffic. Prices are USD cents. The initial shipping jurisdiction is US; configure tax basis points, shipping cents and the free-shipping threshold for your business. The included flat tax policy is not a jurisdiction-aware tax engine. Review tax, returns, privacy, legal operator details and support contact before taking real orders. Seed photos illustrate products and are not manufacturer assets; replace them with licensed product photography and verified specifications.

## Payments and uploads

COD works without Stripe. For sandbox cards set `PAYMENT_PROVIDER=stripe`, `STRIPE_SECRET_KEY=sk_test_...` and the matching `STRIPE_WEBHOOK_SECRET`. Register `https://YOUR-DOMAIN/api/webhooks/stripe` for `checkout.session.completed` and `checkout.session.async_payment_succeeded`. Use Stripe CLI forwarding locally. Online sessions reserve inventory for 30 minutes; abandoned sessions release through the scheduler. Payment amount/currency/order/session are verified and events deduplicated transactionally. A late payment enters a durable refund queue. Full refunds are available for paid, unshipped or delivered card orders; shipped orders must first be delivered. Returned goods require manual inspection and inventory adjustment. COD refunds require an offline refund process; no provider transfer is simulated.

Set all three Cloudinary variables for authenticated admin uploads. Files are limited to 4 MB; JPEG/PNG/WebP signatures are checked and Cloudinary re-encodes uploads. Do not expose API secrets in NEXT_PUBLIC variables.

## Verify

`npm test` runs pricing/validation and real MongoDB replica-set integration tests (first run downloads MongoDB). If download is restricted, set `MONGOMS_SYSTEM_BINARY` to an installed mongod executable. `npm run build` compiles the production application. `npm run test:e2e` launches an isolated seeded replica set and production server and exercises real HTTP authentication, checkout, ownership, admin fulfillment and reviews with Playwright's request runner. No payment network is mocked as a successful live payment. Browser visual checks are separate. `npm audit --omit=dev --audit-level=high` checks production dependencies. CI runs these commands. Never aim test-server.js at production; it creates an ephemeral database and test-only accounts.

## Deploy to Vercel

Import this directory as the repository root, framework Next.js, Node 24, default build `npm run build`. Add environment variables in Vercel; production and preview must use separate databases/payment secrets. Add the Vercel deployment egress IPs to Atlas using your plan's networking controls. Use least-privilege database access, backups and monitoring. Run seed once against the intended database before launch. Set the canonical HTTPS URL in AUTH_URL and NEXT_PUBLIC_SITE_URL, AUTH_SECRET and a random CRON_SECRET (32+ bytes). Configure Stripe's production webhook against the canonical domain and verify test-mode checkout, duplicate events, refund recovery and uploads before switching to live keys. Do not use demo/test accounts in production.

`vercel link`, `vercel env add NAME production`, then `vercel --prod`. The default Vercel cron runs daily so Hobby deployments succeed; this alone is insufficient for checkout. On Pro/Enterprise copy `vercel.pro.json` over `vercel.json` for minute execution. On Hobby configure an external durable scheduler calling GET `/api/cron` every five minutes with `Authorization: Bearer CRON_SECRET`. The included GitHub Actions maintenance workflow does this once STORE_URL and CRON_SECRET repository secrets are configured, the ENABLE_ORDER_MAINTENANCE repository variable is set to true, and Actions is enabled (GitHub scheduling can be delayed). Online checkout fails closed unless a successful maintenance heartbeat occurred in the last 15 minutes. COD orders reserve stock until fulfillment or explicit admin cancellation and do not depend on reservation expiry. Invoke the endpoint once after scheduler setup to initialize that heartbeat. The cron processes bounded batches and is safe under concurrent delivery. Monitor backlog and invocation failures; increase cadence/workers as volume grows. Provider refund retries are persisted in orders. No in-process timers are used.

## Operations and limits

Admin inventory numbers mean units available for new orders. Existing SKU identities are immutable, products are archived rather than deleted, and edits require an unchanged updatedAt version to avoid overwriting concurrent reservations. Keep promotions under Coupons and product featured flags. Audit logs persist administrative changes in MongoDB. Rate limiting is shared across instances using TTL-indexed MongoDB buckets. Authentication checks reload users for immediate role/disable enforcement. APIs validate ownership and reject foreign mutation origins. Change passwords or bootstrap an admin only through a trusted operator workflow; public registration cannot grant admin roles.

JWT sessions last one day. Both roles change passwords under Profile & security; current-password verification and a session version invalidate all previous sessions. Email verification, self-service password recovery, carrier integrations, multi-jurisdiction tax, partial refunds, automated COD refunds and fraud screening are not included. Catalog reads are live to show inventory; static policy/assets and Next image optimization provide caching. For larger catalogs add tag-invalidated public read caching and search infrastructure. Store operators must add support contacts, observability/alerts and their recovery procedures. This repository is deployment-capable code; production certification still requires real-service acceptance tests and operational configuration.
